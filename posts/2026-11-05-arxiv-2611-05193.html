정답 이미지를 먼저 상상하는 검색 모델, FactEmbed

원문: Factorized MLLM Embeddings for Composed Image Retrieval · arXiv(논문 공개 사이트) 2611.05193 · 2026년 11월 4일 공개

한 줄 요약

FactEmbed는 MLLM(Multimodal Large Language Model, 이미지와 글을 함께 읽는 대형 언어 모델) 기반 이미지 검색 모델이 검색용 벡터를 만들기 전에, 수정이 반영된 정답 이미지를 내부에서 먼저 복원해 보도록 학습시키는 방법입니다. CIRR(일반 사진 분야의 합성 이미지 검색 벤치마크)의 정제판인 Refined-CIRR에서 Recall@1(정답이 맨 위에 오는 질의 비율)은 CSMCIR(검색 대상 이미지마다 설명문을 추가로 쓰는 기존 방식)보다 2.7%, ReCALL(MLLM으로 학습 데이터를 보강하는 기존 방식)보다 2.3% 높았고, 재정렬로 늘어난 시간은 전체 지연의 0.05% 미만이었습니다.

무엇을 했나 원문 내용

무엇이 문제였나: CIR(Composed Image Retrieval, 합성 이미지 검색)은 기준 이미지와 '셔츠의 로고를 바꾼 것' 같은 수정 문장을 함께 받아, 수정이 반영된 목표 이미지를 찾는 작업입니다. 최근 방식은 MLLM에 두 입력을 넣고 마지막 EOS(End of Sequence, 입력 끝을 표시하는 특수 토큰) 토큰의 상태를 검색용 벡터로 씁니다. 원문은 이 방식이 대조 학습(맞는 짝은 가깝게, 나머지는 멀게 만드는 학습)만으로 질의를 벡터 하나에 바로 대응시켜서, 문장이 무엇을 바꾸고 무엇을 남기라고 하는지 따로 풀어 볼 학습 신호가 없다고 지적합니다.

정답을 먼저 상상하게 하기: FactEmbed는 [EOS] 앞에 학습 가능한 토큰 묶음인 factorized latents(장면을 요소별로 나눠 담는 분해 토큰)를 넣습니다. 학습 중에는 MLLM 중간 층에 가벼운 디코더(복원용 보조 신경망)를 달고, 이 토큰들로 목표 이미지의 패치(이미지를 잘게 나눈 조각) 특징을 복원하게 합니다. 원문은 이 과정을 target imagination(목표 상상)이라고 부릅니다. 디코더에는 목표 이미지를 아주 거칠게 줄인 배치 정보가 함께 들어가므로, 토큰은 그 배치 정보로 설명되지 않는 세부를 맡습니다. 원문 시각화에서 토큰별 담당 영역은 팔·다리·목선 같은 부위로 나뉘었습니다. 질의 쪽 토큰은 목표 이미지를 보지 못한 채 기준 이미지와 문장만으로 이 세부를 맞혀야 합니다.

검색으로 연결하기: 복원을 잘해도 검색에 쓸모가 있다는 보장은 없어서 장치 두 가지를 더합니다. 하나는 질의와 목표의 분해 토큰을 OT(Optimal Transport, 두 집합의 원소를 가장 잘 맞게 짝짓는 계산)로 짝지은 점수에 InfoNCE(대조 학습에 흔히 쓰는 손실 함수)를 적용하는 것이고, 다른 하나는 디코더가 만든 토큰별 영역 지도를 MLLM 위쪽 층의 주의 분포가 따라 하도록 학습시키는 증류입니다. 검색할 때는 모델을 한 번 통과시키는 계산에서 [EOS] 벡터와 분해 토큰의 평균 벡터가 함께 나옵니다. [EOS] 벡터로 전체 이미지에서 상위 100개 후보를 고른 뒤, 이 후보만 두 벡터의 코사인 유사도 합으로 다시 정렬합니다. 마지막 추가 학습 단계에서는 자기 모델이 정답보다 위에 올린 헷갈리는 오답을 모으고, 배치 API로 호출한 GPT 모델에게 원래 정답까지 보여 주며 그 오답에만 맞는 새 수정 문장을 쓰게 했습니다.

결과: 원문은 원본 CIRR과 FashionIQ(패션 상품 검색 벤치마크)에서도 전체적으로 가장 좋은 결과를 보고합니다. 구성 요소 제거 실험에서 전체 모델은 같은 추가 학습 단계만 적용한 기본 모델보다 CIRR Recall@1이 2.91포인트 높았습니다. 반면 보조 학습 목표 없이 토큰만 넣은 모델은 재정렬까지 써도 Refined-CIRR 평균 점수가 73.21로, 토큰이 없는 기본 모델(74.65)보다 낮았습니다. 추가 학습 전 같은 조건에서 FactEmbed는 76.05였습니다. 재정렬을 쓰는 기본 설정과 토큰 전체를 저장해 짝짓는 방식의 CIRR Recall@1 차이는 0.24포인트였고, 재정렬로 늘어난 시간은 질의를 하나씩 처리할 때 질의당 0.17ms였습니다. 기반 MLLM을 같은 Qwen 계열의 다음 세대 모델로 바꾸자 CIRR Recall@1이 2.65포인트 올라, 같은 교체에서 ReCALL이 보고한 1.60포인트보다 컸습니다.

한계·반론 원문 내용

  • 고정된 토큰 개수와 평균 내기: 원문은 분해 토큰 개수가 입력의 복잡도와 무관하게 고정돼 있고, 효율을 위해 토큰을 평균 내 재정렬에 쓰면서 세부 정보 일부를 활용하지 못한다고 밝힙니다. 실제로 토큰 전체를 저장해 짝짓는 방식의 Recall@1이 조금 더 높습니다.
  • 좁은 평가 범위: 평가는 CIRR과 FashionIQ 두 벤치마크뿐이라 범용 멀티모달 검색기로 쓸 수 있는지는 추가 검증이 필요하다고 원문이 적었습니다. 증강 방식도 같은 질의에서 나온 여러 오답끼리의 모호함은 줄이지 못한다는 한계를 원문이 따로 밝혔습니다.
  • 비교 조건: 기본 모델과 ReCALL은 공개된 학습 결과물이 없어 저자들이 처음부터 다시 학습한 수치이고, 표에는 반복 실행 편차가 없습니다. 원본 CIRR과 FashionIQ 표의 일부 지표에서는 CSMCIR이 FactEmbed보다 높습니다.
  • 증강 품질 판정: 수정 문장 품질 비교는 데이터셋마다 표본 100개로 했고, 판정은 새 수정 문장을 쓴 것과 같은 GPT 모델이 맡았습니다.

🛠️ 기술

결론부터 말하면 좋은 논문입니다. 사람이 '이 옷에서 소매만 길게'를 찾을 때 머릿속으로 먼저 떠올려 보듯, 모델에게도 검색 전에 정답을 상상하는 연습 문제를 내 준 셈입니다. 저는 코드를 돌려 보지 않았고 원문 표만 읽었으니 그 범위에서 평가합니다. 가장 쓸모 있는 교훈은 구조 자체보다 구성 요소 제거 실험에 있습니다. 토큰을 더 넣으면 담을 공간이 늘어나니 당연히 나아질 것 같은데, 이게 맞을까요? 보조 목표 없이 토큰만 넣은 모델은 토큰이 없는 기본 모델보다 낮았습니다(73.21 대 74.65). 중간 표현은 무엇을 담을지 감독받을 때만 쓸모가 생긴다는 뜻이고, 멀티 벡터 검색, 에이전트의 메모 칸, 추론용 중간 토큰처럼 '칸을 더 주는' 설계 전반에 적용해 볼 만한 교훈입니다. 생각난 김에 덧붙이면, 원문 첫 번째 표의 점수로 직접 나눠 보면 요약의 2.7%는 점수 차를 기존 점수로 나눈 상대 향상률이라 포인트 차이로는 이보다 작습니다.

평가·자기개선 루프 관점에서도 볼 거리가 있습니다. 마지막 추가 학습은 자기 모델이 틀린 사례를 모아 LLM에게 새 학습 문장을 쓰게 하고 다시 학습하는 루프입니다. 핵심은 생성 모델에게 헷갈리는 상대인 원래 정답을 함께 보여 준 것입니다. 기존 두 이미지 방식은 CIRR 표본의 27.0%에서 수정 문장을 그대로 돌려줬고, 새 문장이 오히려 원래 정답을 더 잘 설명하는 역전 비율은 CIRR 기준 기존 방식 30.1%에서 원문 방식 7.0%로 줄었습니다. LLM으로 라벨이나 평가 데이터를 만들 때 '비교 대상을 같이 보여 주기'는 어디에든 쓸 수 있는 장치입니다. 운영 측면도 같은 교훈을 줍니다. 로컬 MLLM 캡션 생성기는 CIRR에서 37%가 첫 시도에 출력 형식을 어겼고, 원문은 지시를 잘 따르는 모델로 바꿔 재시도 루프와 별도 검증 단계를 없앴습니다. 아쉬운 점은 품질 판정을 생성에 쓴 같은 모델이 했다는 것입니다. 증강 데이터를 만드는 팀이라면 생성 모델과 판정 모델부터 분리해봅시다. 원본 벤치마크와 정제판 사이 점수 차가 CIRR Recall@1 기준 최대 13.7포인트(차이가 가장 큰 범용 모델 하나 제외)까지 난다는 결과도, 모델을 고치기 전에 평가셋 정답부터 점검해야 한다는 근거입니다.

💼 사업

사업 쪽에서 가장 직접 관련 있는 곳은 패션·커머스 검색입니다. 고객이 상품 이름 대신 '이 원피스에서 무늬만 동물 무늬로'처럼 기존 상품을 기준으로 바뀔 점을 말하는 검색이라면 이 방식이 다루는 문제와 같습니다. 원문 사례에서도 기본 모델이 '슈퍼맨 로고 말고' 같은 부정 조건을 놓친 질의를 FactEmbed가 더 잘 처리했습니다. 비용 구조는 비교적 명확합니다. 재정렬 비용은 전체 지연의 0.05% 미만이고 저장량은 이미지당 벡터가 하나 늘어나는 수준입니다. 대신 원문 측정 환경에서 질의를 하나씩 처리하면 질의를 벡터로 바꾸는 계산이 질의당 353ms로 대부분을 차지합니다. 도입 비용의 핵심은 재정렬이 아니라 질의마다 대형 모델을 돌리는 GPU 비용인 셈이죠. 학습 데이터 보강 비용은 CIRR $22.82, FashionIQ $26.17로 원문에 나와 있어서 데이터 만들기는 진입 장벽이 아닙니다.

다만 도입 판단은 쉽지 않습니다. 기존 강한 방식과의 차이가 크지 않고 평가도 두 벤치마크에 그칩니다. 원본과 정제판 점수가 크게 다르다는 원문 결과를 보면, 공개 벤치마크 순위보다 자사 상품과 실제 고객 질의로 만든 평가셋 결과가 더 믿을 만한 근거입니다. 팀에서는 검색 품질을 실제 고객 질의로 재고 계신가요? 검토한다면 원문이 공개하겠다고 밝힌 증강 데이터와 방법을 자사 평가셋에서 먼저 돌려 보는 순서가 맞습니다.
